# 十电荷问题：一条经过 Lean 核验的距离限制

本发布包的237份证明源码已从最初为空的项目编译目录全部重新构建，续跑时核对了已有源码、产物和日志的哈希。三个最终定理的公理审计与两项故意改错的拒绝测试均通过。十电荷的全局最优仍未由本项目证明。

在半径为1的球面上放置十个互不重合、同量同性的点电荷，把库仑系数和电荷量归一化后，总能量是45对电荷的“距离倒数”之和。

这里的距离都是两点之间的直线距离。

**已经通过本机 Lean 内核的结论：如果总能量不超过32.717，就一定有一对电荷的距离大于1.935。**

球的直径是2，因此这对电荷的距离必须超过直径的96.75%。同一结论也可以反过来说：如果所有点对的距离都不超过1.935，总能量就一定大于32.717。

这个结论适用于所有满足条件的排列，没有限定它们必须排成某种对称形状。它排除了一类低能量竞争排列，给出了一个必要的几何条件。要确定全局最低能量，还需要处理其他排列。

[剑桥簇数据库](https://www-wales.ch.cam.ac.uk/~wales/CCD/Thomson/table.html)列出的十电荷数值候选能量约为32.71695，低于这里的32.717门槛。这说明本结论约束的是接近最好数值候选能量的排列，而不只是某些能量很高的排列。对能量不超过32.717的排列，必要的点对距离从先前的“大于1.90”加强到了“大于1.935”。数据库的小数在这里作为数值背景；本包严格证明的结论以源码中的能量条件为准。

准确的形式化命题、单位球面条件及点不重合条件见 [最终定理源码](src/M36Chord1935Exclusion.lean)。这份发布记录的是阶段性形式化成果。

## 自行检查

版本固定为 Lean 4.34.1 和清单指定的数学库版本。安装对应工具后，在本目录执行：

```text
lake exe cache get
python verify.py --package-root . --seconds 16200
```

验证器先检查文件是否齐全、内容哈希与依赖版本是否一致，然后从源码逐个重新编译项目证明。它还会核对最终定理使用的公理，并要求 Lean 拒绝两个被故意改坏的命题。

只有 `--static-only` 的检查通过，表示文件结构和版本清单通过检查，并不表示证明已经重新构建。构建可中断；下次可以用 `--resume .verification-output/<运行编号>` 接着检查，已经通过的源码、产物和日志必须保持一致。

上述命令允许一轮最多4.5小时，仍逐个编译、每个命令最多10分钟。未指定 `--seconds` 时默认85分钟。续跑时同样可以加上 `--seconds 16200`；总时长到期会保存进度，不代表证明有错。
